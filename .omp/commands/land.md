Land the completed task from this session. This invocation explicitly authorizes a task-only commit on its dedicated worktree branch, integration into local `main` including automatic merge-conflict resolution, closure of its completed bead, and removal of that exact worktree and merged branch. It does not authorize pushing, fetching, pulling, remote sync (including Dolt), or unrelated cleanup. Do not treat ending a session or a previous invocation as standing authorization.

Follow repository instructions and the Beads workflow. This is an explicit owner-directed operation, not automatic lifecycle-controller closure or retention cleanup.

1. Resolve the canonical repository/main checkout, shared Beads database, exact task bead, dedicated linked worktree, and branch from this session and repository evidence. Read the bead and current ownership. If identity is ambiguous, the branch is `main`, the task is incomplete, another owner/writer is active, or a bound run requires a different integration target/workflow, stop and report the exact blocker. Never guess a bead from a directory name alone, close an epic, or operate on another task's worktree.
2. Inspect task changes, the index, and both checkouts. Preserve unrelated tracked, staged, untracked, and ignored files, stashes, nested repositories, and commits. Never auto-stash, reset, clean, force, or stage everything indiscriminately. If unrelated staged changes or a dirty integration checkout prevent safe progress, stop without changing them.
3. Run the relevant repository quality gates and a smoke scenario covering the changed behavior. Use existing trustworthy results only when they cover the exact revision being landed. On failure, stop before commit/merge/closure/removal and report the command and failure; never bypass hooks or checks.
4. Stage only this task's changes and commit with an appropriate message on the worktree branch. Reuse an existing task commit if no further task changes remain. Verify that every commit to be integrated belongs to this task; stop if unrelated commits would be included. Record the submitted commit ID.
5. From the canonical main checkout, merge the task branch into local `main` using the repository's merge convention (ordinary `git merge` if none is specified). Do not change the worktree branch to `main`. Resolve merge conflicts automatically without asking for confirmation: inspect the merge base and both sides, reconcile the changes while preserving the task's intended behavior and unrelated changes on `main`, and stage only the resolved paths. Never blindly choose `ours` or `theirs`, discard changes to make the merge pass, or bypass hooks or checks. Before completing a conflicted merge, verify that no unmerged paths or conflict markers remain and rerun the relevant quality gates and smoke scenario on the resolved tree; then complete the merge commit. If a resolution cannot be determined safely from repository evidence or validation fails, stop, retain the bead, branch, worktree, and merge state, and report the exact blocker; do not guess or roll back unrelated work. Verify the submitted commit is an ancestor of local `main`, then run any required post-merge checks. If checks fail, retain the bead, branch, and worktree and report the state; do not roll back unrelated work.
6. Re-read the bead's current status and ownership before closing it. If ownership or task identity changed, stop. Close only the completed task with ordinary `bd close <exact-id> --reason "..."`, recording the integrated commit as evidence; do not use `--force`, retry a refused closure blindly, or mutate other beads. If already closed, report that rather than reopening it. Stop before cleanup if closure fails.
7. Before cleanup, recheck the exact worktree for tracked, untracked, ignored, nested-repository, stash, unmerged-commit, and active-writer risks. Preserve transcripts and session history. Respect any bound session's supported release/relocation requirements. Run cleanup from the canonical main checkout, never from the directory being removed. If safe session release/relocation or preservation cannot be established, retain the worktree and branch and report why. Remove only this linked worktree with non-forced `git worktree remove <exact-path>`, then delete only its merged branch with `git branch -d <exact-branch>`. Never use recursive filesystem deletion, `git branch -D`, bulk worktree clearing, or broad pruning as a substitute. `git worktree prune` alone does not remove a live worktree.
8. Report the task and integration commit IDs, exercised checks, bead status, and whether the exact worktree and branch were removed. Report partial completion precisely on any blocker. Do not push or sync remotes.
